 v2.1.2                                        2026-09-27
 类型：缺陷修复（小版本）

【修复 1】开机自启"显示已开启、实际从来没启动过"

  ● 现象
    界面上的「开机自启」开关一直是「已开启」，但每次开机/登录 Windows 之后，
    后台保活都没起来，网络要手动打开程序登录一次。重开关、重装都没用。

  ● 根因（两个叠在一起）
    1) 系统里那条自启登记指向了一个**早就删除的旧目录**：
         HKCU\...\Run\CampusLoginApp
           = "D:\first-cc\校园网正式版\CampusLogin.exe" --daemon
       而实际程序在 D:\first-cc\校园网一键登录-作者包\CampusLogin.exe。
       Windows 开机如实去执行那个不存在的路径，然后静默什么都不做。
       目录被删/换位置后，旧登记是不会被清理的，于是长期留在那儿。
    2) 程序的判断只看「有没有登记项」，不看「登记指向的是不是自己」：
         autostart_enabled() { return 任务存在 or Run 值存在 }
       于是这条失效登记照样被算成"已开启"——界面亮着绿灯，功能其实是死的。

  ● 修复
    src/app.py 把自启登记改成**三态判定**（不只回答"有/没有"）：
      current = 指向本程序                 -> 真的生效
      foreign = 指向另一个还在的副本        -> 界面如实说明"起的是另一份"
      missing = 指向的文件已经不存在        -> 视为失效，并按废弃项处理
    具体：
      1. autostart_state() 一次性把计划任务 + 注册表里每条登记的命令行、
         目标文件、三态都取回来；
      2. autostart_enabled() 改为只有 current 才算「已开启」（不再亮假绿灯）；
      3. GUI 启动时在后台线程扫一遍失效登记并自动清理，同时给一条说人话的
         回执：清理了什么、指向哪个已不存在的文件、要不要重开开关；
      4. register_autostart() 开注册前先清干净陈旧残留，避免"新的没生效、
         旧的失效项还占着位"；
      5. unregister_autostart() 的判定从"有没有开成功"改成"有没有登记项"，
         失效残留也能被真正删掉；
      6. 界面能区分"自启开着，但开的是另一份副本"这种情况并给出路径。

  ● 结果
    本机那条失效登记已清理，重新登记为当前 exe；开关状态与真实情况一致。
    以后换目录、删旧副本都不会再出现"说开了却不开机启动"。

  ● 影响文件
    src/app.py   主修复（自启三态判定 / 清理 / 注册与注销 / 界面回执）


【修复 2】顺便：pythonw / 源码调试环境下的自启自判
    源码模式（python app.py）下原本会把<｜hy_place▁holder▁no▁813｜>的 CampusLogin.exe 登记判成
    "别人"，现在会把同一分发目录里的 exe 认作自己人。

【修复 1】后台保活进程在任务栏通知区域（"状态栏"）显示软件图标

  ● 现象
    后台保活跑了一段时间后，任务栏右下角的通知区域里会多出一个校园网图标，
    鼠标悬停显示"校园网保活：正在运行"。点它没有任何反应，而且不管等多久
    都不会自己消失，只能等后台进程退出才一起不见。

  ● 根因
    src/notify_win.py 为了让「校园网已恢复连接」「校园网已让位给其他设备」
    这两条气泡提醒有个落点，在通知线程一启动就调用 Shell_NotifyIconW(NIM_ADD)
    把图标挂到了通知区域，但**从头到尾没有调用过 NIM_DELETE**。承载图标的那个
    消息窗口又是常驻不退出的，于是图标一旦挂上就永久停留在通知区域。
    气泡提醒本身只在「断网/未认证 → 在线」或「账号被其他设备顶掉」时才触发，
    所以用户侧看到的就是"莫名其妙冒出来、又赶不走"的图标。

  ● 修复
    把图标从"常驻"改成"按需挂载 + 弹完即卸"：
      1. 通知线程启动时不再挂任何图标（原来就是在这里常驻的）；
      2. 真要弹气泡时才临时 NIM_ADD，并同时请求 NIS_HIDDEN，让系统尽量
         连这短暂的一下都不要画出来；
      3. 气泡读完后 ICON_LINGER_SECONDS（8 秒）自动 NIM_DELETE 摘掉；
      4. 线程异常退出 / 调用 stop() 时兜底摘除，绝不留残留。

  ● 结果
    后台保活进程在任务栏通知区域全程不显示图标。
    只有在真的触发「恢复连接 / 让位提醒」时图标才短暂出现最多 8 秒
    （气泡必须有落点），随后自动消失。

  ● 影响文件
    src/notify_win.py   主修复


【修复 2】打包脚本 build.bat 漏打 app.ico，导致程序图标显示不对

  ● 现象
    用 src\build.bat 重新打包出来的 exe，标题栏与任务栏上显示的是 tkinter
    默认的那个羽毛图标，而不是校园网图标。

  ● 根因
    PyInstaller 的 --icon 参数只设置 **exe 文件自身的图标资源**，并不会把 ico
    放进运行时的解包目录 _MEIPASS。而程序运行时要设窗口图标，走的是
    root.iconbitmap(assets/app.ico)，frozen 环境下由 asset_path() 到 _MEIPASS
    里找。build.bat 的 pyinstaller 命令行里**漏了这条**：
        --add-data "%ASSETS%\app.ico;assets"
    于是 frozen 下找不到 ico，iconbitmap 静默失败，图标就退回了 Tk 默认样式。
    同一条命令行还漏了 --hidden-import notify_win（notify_win 是在 login_core
    的函数里惰性 import 的，漏收后线上表现只是"气泡永远不弹"，同样是静默故障）。

  ● 对照
    内部一直在用的 _内部工具与备份\build_exe.py 里这两条参数是有的，所以它打
    出来的包图标正常。build.bat 是后来重写的"给用户的一键打包脚本"，抄参数时
    漏掉了这两条——属于典型的"两套打包入口参数不同步"。

  ● 修复
    src\build.bat 补上这两条参数，并加注释说明为什么不能省。

  ● 验证
    重新打包后，CampusLogin.exe --gui-smoke 里专钉此事的断言
    icon_resources_packaged 由 FAIL 转为 PASS。

【说明】任务管理器里为什么会看到 2 个（或 4 个）CampusLogin.exe

  这是 PyInstaller 单文件（onefile）打包的正常机制，不是重复启动、更不是异常：

      1 号进程  启动壳（bootloader）
                把压缩在 exe 里的运行库解包到 %TEMP%\_MEIxxxxxx，
                拉起真正的程序后安静等待它结束。
                任务管理器里那个标题为「PyInstaller Onefile Hidden Window」
                的不可见窗口就属于它。

      2 号进程  真正的程序本体，实际干活的就是它。

  所以：只开后台保活 → 2 个进程；同时开着图形界面 → 4 个进程（界面同样是一对）。
  实测后台稳定占用约 3 MB 内存、CPU 长期 0%（每 30~60 秒做一次网络探测）。

  已实测确认（_内部工具与备份/probe_windows.py）：后台保活进程不持有任何
  可见窗口，因此**不会**在任务栏上产生程序按钮，也不会进 Alt+Tab。


【升级后的一次性手工清理（可选）】

  旧版本在通知区域留下的图标"记录"会被 Windows 记住（即使图标已经不显示了），
  表现为「设置 → 个性化 → 任务栏 → 其他系统托盘图标」里还留着校园网的条目。
  想彻底清干净可以二选一：

    · 手动：在上面的列表里把 CampusLogin 那一项右侧的下拉框改为「无」；
    · 脚本：删除注册表 HKEY_CURRENT_USER\Control Panel\NotifyIconSettings
            下面 ExecutablePath 指向 CampusLogin.exe 的子项（删前先导出备份）。

  注意：这是 Windows 自己的历史记录，不是程序还在偷偷挂图标；v2.1.1 起
  程序本身不会再往通知区域挂任何常驻图标。
